# 月净需求计算逻辑

## 1. 目的

月净需求用于计算指定计划月份内，各个特力物料在扣减现有可用资源后仍需补充的数量。

```text
净需求 = MAX(总需求 - SAP 可用库存 - 驻外库存 - 在制订单, 0)
```

当前“在制订单”使用采购未清订单的 `open_qty` 作为计算口径。

## 2. 数据来源

| 数据 | 来源表 | 使用字段 | 取数口径 |
| --- | --- | --- | --- |
| 主机营销计划 | `buyer_vehicle_plan` | 产品机型、2026 顺序号、台份数量、计划月份 | 只使用最新 `import_date` 版本中所选月份的数据 |
| 车型配置 | `buyer_vehicle_config` | 车型、2026 顺序号、主机编码、单台配置数量 | 只使用最新 `import_date` 版本 |
| 主机/特力编码映射 | `buyer_code_config` | 主机编码、特力编码、物料名称 | 使用未删除的有效映射 |
| SAP 可用库存 | `real_time_stock` | 物料号、可用数量 | `deleted = 0`，且状态为 0 或空 |
| 驻外库存 | `buyer_overseas_inventory` | 货品编码、可用量 | 使用未删除数据 |
| 在制订单 | `buyer_open_order` | 物料号、未清数量 | 使用未删除数据，汇总 `open_qty` |

所有参与计算的空数量均按 0 处理。

## 3. 计划月份确定规则

主机计划导入时按照以下优先级生成标准化的 `plan_month`，格式为 `yyyy-MM`：

1. 臂架上下线计划日期，即 `boom_top_bottom_plan_date`；
2. 如果臂架上下线计划日期为空或为 `/`，使用转台计划日期 `turntable_plan_date`；
3. 如果前两项均无有效值，使用成台完工计划日期 `finished_product_plan_date`。

查询月净需求时，根据用户选择的月份直接匹配 `plan_month`，并且只查询主机计划中最新导入版本的数据。

如果高优先级日期有值但格式无法解析，该计划的 `plan_month` 为空，不继续使用低优先级日期兜底。

## 4. 总需求计算

### 4.1 匹配车型配置

每条主机计划首先使用以下组合精确匹配车型配置：

```text
产品机型 + 2026 年度顺序号
```

如果精确匹配不到配置，则使用该产品机型下“数值顺序最大”的配置作为兜底。

顺序号按其中出现的数字分段比较。例如 `2026-10` 大于 `2026-9`，不是简单按照字符串大小比较。

车型配置数据会先按以下维度合并：

```text
车型 + 2026 年度顺序号 + 主机编码
```

同一组合下的 `required_quantity` 相加，得到该主机编码的单台配置数量。

### 4.2 计算单项需求

一条计划匹配到一条物料配置后的需求量为：

```text
单项需求 = 主机计划台份数量 × 车型配置单台物料数量
```

同一条主机计划可能展开为多条物料需求。

### 4.3 映射特力物料编码

车型配置中的 `material_desc` 作为主机编码，通过 `buyer_code_config.host_code` 查找对应的特力编码 `teli_code`。

- 映射成功：按最终特力编码汇总总需求；多个主机编码映射到同一特力编码时合并为一条结果，并保留全部主机编码。
- 映射失败：该项需求仍保留，映射状态显示为“未映射”，使用主机编码区分不同结果。

一个特力物料的总需求为：

```text
总需求 = Σ（各主机计划台份数量 × 对应配置的单台物料数量）
```

## 5. 可抵扣数量计算

系统只对本月需求实际涉及的、已经成功映射的特力物料编码查询库存和订单，并按物料编码分别汇总：

```text
SAP 可用库存 = Σ real_time_stock.available_quantity
驻外库存     = Σ buyer_overseas_inventory.available_quantity
在制订单     = Σ buyer_open_order.open_qty
```

三类数据通过一条合并查询返回。物料数量超过 Oracle `IN` 条件限制时，每 900 个物料分为一批查询，最终在业务层合并。

未映射物料无法可靠关联特力库存及订单，因此其 SAP 可用库存、驻外库存和在制订单均按 0 计算。

## 6. 净需求计算

每个物料完成总需求和三类可抵扣数量汇总后，按以下公式计算：

```text
差额 = 总需求 - SAP 可用库存 - 驻外库存 - 在制订单
净需求 = MAX(差额, 0)
```

当库存和订单合计大于总需求时，净需求显示为 0，不显示负数。

示例：

| 项目 | 数量 |
| --- | ---: |
| 总需求 | 100 |
| SAP 可用库存 | 20 |
| 驻外库存 | 10 |
| 在制订单 | 30 |
| 净需求 | 40 |

计算过程：`MAX(100 - 20 - 10 - 30, 0) = 40`。

## 7. 页面查询与排序

系统完成所选月份的全部物料计算后，支持按照以下条件过滤：

- 物料编码：同时匹配特力物料编码和主机编码，使用包含匹配；
- 物料名称：使用包含匹配；
- 映射状态：已映射或未映射。

结果默认按照以下顺序排列：

1. 已映射数据优先；
2. 净需求从大到小；
3. 特力物料编码升序；
4. 主机编码升序。

过滤和排序完成后再进行内存分页，因此分页总数是过滤后的实际物料数量。

## 8. 缓存与数据实时性

- 车型配置按其最新导入版本缓存；最新 `import_date` 变化时自动刷新。
- 主机/特力编码映射按最新更新时间缓存；映射数据变化后自动刷新。
- SAP 可用库存、驻外库存和采购未清订单不缓存，每次查询实时汇总。
- 月净需求结果本身不保存，计划、配置、映射、库存或订单变化后，重新查询即可得到最新计算结果。

## 9. 计算流程概览

```text
选择计划月份
    ↓
读取最新版本的当月主机计划
    ↓
按“车型 + 2026 顺序号”匹配车型配置
    ↓（匹配失败时使用该车型最大顺序号配置）
计算台份数量 × 单台配置数量
    ↓
主机编码映射为特力物料编码
    ↓
按特力编码汇总总需求
    ↓
汇总 SAP 库存、驻外库存、采购未清订单
    ↓
计算 MAX(总需求 - 三类可抵扣数量, 0)
    ↓
按查询条件过滤、排序并分页返回
```
